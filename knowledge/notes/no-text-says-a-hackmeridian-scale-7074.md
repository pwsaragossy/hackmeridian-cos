# No text says a HackMeridian Scale repo must hold only new code (checked 2026-10-25)

Question: do the event rules say that only new code may be in the hackathon repo? Checked 2026-10-25 against Pedro's verbatim paste of the portal pages and three text files (identical wording, see [[hackmeridian-2026-rules-and-submission-requirement-5868]]), plus the raw HTML of /build, /faq and /terms.html (read directly this time, not through a summarising tool).

[FACT] Not found in any of these: no sentence says the repo may hold only new code, that existing code must be left out, or that a closed component must or must not be published. The word "only" does not occur next to code or repo anywhere.

[FACT] Text that supports reading A (repo shows the new work): Scale requires "Substantive new work completed during HackMeridian, clearly distinguished from existing functionality"; judging says "you still need to show new work from the event"; terms sec 06 defines Submissions as the projects, code and designs "you create for the Event".

[FACT] Text that supports reading B (existing code allowed): "You may start with an existing project"; "Using an existing codebase is fine if you declare it. Undisclosed prior work is a disqualification"; Scale is "Bring an existing Stellar-based MVP"; starting point and new work must be clear "in your README and demo". The only stated disqualifier is undisclosed prior work.

[FACT] The one open phrase: "Public GitHub repository containing the project source code". "The project" is not defined for Scale, so whether it means the whole product or the submitted work is not answered by the text. [INFERENCE] The plan (public repo with the new work, closed backend declared as prior work) breaks no sentence found; its residual risk is a mark-down on Technical Execution, not a stated disqualification.

Not read: the live portal rules page (login), the Liability Waiver, any Genesis-only rules. The Code of Conduct was read later by the reviewer: its "only your own work" limits whose work, not when it was written, and is the likely source of Pedro's memory ([[hackmeridian-code-of-conduct-play-fair-4f3e]]). The real exposure is that the Scale text calls the pre-existing product "project", so "the project source code" could be read as the closed Radox platform.
